# First-Use Tutorial Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A practice page at `/tutorial` that plays a recorded measles-in-Kenya conversation through ten do-it steps centred on the Dashboard, offered to new and existing participants, with counts for researchers.

**Architecture:** The practice page composes the app's existing workspace components (`WorkspaceShell`, `Turn`, `Suggestions`, `PanelTabs`, `DetailsPanel`), fed by a recording file, and never calls the chat. A pure state machine (`lib/tutorial/machine.ts`) over a step list (`lib/tutorial/steps.ts`) decides what is shown and what completes a step; a spotlight overlay dims everything but the current target. "Seen" lives in `profiles.tutorial_seen_at`, set by the event route; counts come from `step_events`.

**Tech Stack:** Next.js 16 (read `web/node_modules/next/dist/docs/` before using any routing or page API; `params` and `searchParams` are Promises, as in `app/chat/[id]/page.tsx`), React, Tailwind 4, zod, vitest (node environment: `renderToStaticMarkup` and source-reading tests), PGlite for migration tests (`tests/db/helpers.ts`), Supabase.

**Spec:** `docs/superpowers/specs/2026-11-21-tutorial-design.md`. Its step table and card texts are binding; this plan does not repeat them.

## Global Constraints

- The tutorial sends no message, saves no conversation or turn, starts no run, uses no daily turn. Files under `web/components/tutorial/` and `web/app/tutorial/` must not contain `/api/chat`, `/api/feedback`, `/api/shares`, `/api/profile`, `/api/runs` or `/api/reports`.
- `Chat.tsx`'s behaviour is unchanged except: an optional offer card on the start page and the "Tutorial" item in the account menu.
- Shared components gain only optional props; with the props absent they render byte-for-byte as before.
- Event meta holds fixed words and numbers only. Steps are numbered 0 to 10.
- English only. The panel is "Dashboard"; its tabs are "This conversation" and "Profile".
- Migration file `web/supabase/migrations/0009_tutorial.sql`, safe to run twice, applied by the owner before the preview check. `COLUMNS` in `lib/profiles.ts` may name `tutorial_seen_at` only because of that.
- No number, source, parameter or chart value in the recording is edited by hand; hand edits (trimmed suggestions, shortened prose) are listed in `web/data/tutorial/NOTES.md`.
- Commit messages end with `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>` and `Claude-Session: https://claude.ai/code/session_016eXYLxC75PS9hTJQ9tQPjd`.
- Commands, in `web/` (needs the `node_modules` junction: `cmd //c "mklink /J web\\node_modules ..\\..\\..\\web\\node_modules"` from the worktree root): `npx vitest run <file>`; whole gate `npx vitest run && npx tsc --noEmit -p . && npm run -s lint`. Write test files with the Write or Edit tool, not shell heredocs (the shell eats backslashes; files are CRLF).

## Review Focus

1. The window crossing 1024 px in the middle of a Dashboard step: the card must ask for the Dashboard button when the sheet is closed, and not when the column is showing (Task 4).
2. A reload half-way: the tutorial resumes at the same step instead of restarting, and is not logged as a replay (Tasks 4 and 7).
3. Presses that are not the current step's action (a double press, a different section, a key press on a dimmed control): nothing changes (Task 4).
4. A target that is not on screen (scrolled away, or missing): it is scrolled into view; if it cannot be found within 2 seconds the card offers **Next** so nobody is stuck (Task 6).
5. A recording that is missing or malformed: `/tutorial` sends the participant to `/chat` rather than crashing (Tasks 5 and 7).

```ts
// steps.ts
export type TutorialAction =
  | { type: "start" } | { type: "example" } | { type: "reply" } | { type: "option" }
  | { type: "section"; section: DetailsSection; open: boolean }
  | { type: "view"; view: ChartView } | { type: "tab"; tab: PanelTab }
  | { type: "dashboard" } | { type: "next" } | { type: "finish" };
export type Target = "centre" | "example" | "reply" | "option" | "dashboard-button" | "tab-profile"
  | "panel-scenario" | "panel-data" | "panel-parameters" | "panel-runs" | "panel-report" | "view-incidence";
export type Part = {
  target: Target; text: string;
  /** The action that completes the part. */
  completes: TutorialAction;
  /** Turns of the recording on show once the part is complete; absent: unchanged. */
  showTurns?: number;
  /** The text of the chip, reply or option to press, read from the recording. */
  press?: "example" | "runReply" | "option" | "reportReply";
};
export type Step = { number: number; parts: Part[] };
export const STEPS: Step[];                 // numbers 0..10, card text from the spec
export const DASHBOARD_TARGETS: ReadonlySet<Target>;   // the panel-*, view-* and tab-profile targets
export const OPEN_DASHBOARD_TEXT = "Press Dashboard to open it.";

// machine.ts
export type TutorialState = {
  step: number; part: number; turnsShown: number;
  open: Record<DetailsSection, boolean>; view: ChartView; tab: PanelTab;
  sheetOpen: boolean; finished: boolean;
};
export const INITIAL: TutorialState;        // step 0, part 0, turnsShown 0, every section closed, view "infected", tab "details", sheetOpen false
export function currentPart(state: TutorialState, narrow: boolean): Part;   // the synthetic open-the-Dashboard part when narrow, the target is a Dashboard target and the sheet is closed
export function advance(state: TutorialState, action: TutorialAction, narrow: boolean): TutorialState;   // unchanged unless the action completes currentPart
export function skip(state: TutorialState, narrow: boolean): TutorialState;  // applies currentPart's completing action
export type Logged = { step: number; how: "done" | "skipped" } | null;
export function completedStep(before: TutorialState, after: TutorialState): number | null;   // the step number just finished, for logging
export function restore(saved: unknown): TutorialState | null;   // a state saved to sessionStorage, validated; null when not a valid state
```

Rules the tests pin: completing a part whose target is in the conversation sets `sheetOpen` false; a `section` action that completes a part sets that section open; sections stay as they are otherwise; `advance` with step 10's `finish` sets `finished`.
